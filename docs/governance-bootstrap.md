# Solo-owner source-governance bootstrap

This document describes the one-time A0/B0/W0 bootstrap. It does not confer authority by itself.

- A0 is an owner-authored GitHub Issue whose canonical RFC 8785 payload starts as `pending_witness`. A0 becomes active only after its exact payload and W0 evidence are verified from the Sigstore bundle and production Rekor entry; an append-only Issue lifecycle comment records the derived active/consumed state after the signing step succeeds.
- B0 is the one-time owner-rooted GitHub settings transition. It removes the sole-owner self-review deadlock, preserves the existing successful-check requirements, enables administrator enforcement, and disables the unsafe legacy workflows before W0.
- W0 is authorized by a one-shot child record bound to A0, repository, PR, base/head, sorted paths, binary diff digest, verifier/acquirer digests, B0 state digests, witness-profile digest, expiry, and nonce. It is consumed only after an expected-head-bound normal merge and verified Rekor witness.
- `governance-gate.yml`, `agent-review.yml`, their comments/labels, and the `governance-approved` label are non-authoritative during bootstrap. The optional Reviewer inspection of W0 is advisory, not human approval.
- The trusted witness workflow runs only on `main`. Its token has read-only repository/PR/check access and `issues:write` solely to append a one-shot `witnessing` reservation and final A0-active/W0-consumed lifecycle receipts; it never edits the A0 body. `id-token: write` is used for Sigstore. It has no website token or cross-repository checkout.
- The witness script uses an exact same-repository GitHub REST allowlist and fetches only the PR head ref. The pinned Sigstore action uses its checked-in hash-locked dependencies and needs GitHub, package distribution, Sigstore TUF, Fulcio, and Rekor access. GitHub-hosted runner networking is not a custom egress firewall; this limitation is recorded, with no website credential, scoped GitHub permissions, and fail-closed verification.
- Sigstore uses the immutable `sigstore/gh-action-sigstore-python@790bc6befb9d733738f18d8f895854b453640ec9` pin, Sigstore Python 4.5.0, production Rekor v1 explicitly, staging disabled, and exact GitHub OIDC issuer/certificate identity. After primary signature verification, the workflow captures `trusted_root.json` plus TUF root/timestamp/snapshot/targets metadata from the client’s platformdirs cache, checks the target hash and length against TUF targets metadata, signs the retained TUF evidence manifest in a second bundle, and appends the full evidence bytes to the A0 Issue in digest-bound chunks for durable later verification. A future Rekor protocol transition requires a separately witnessed profile change.
- The former outbound ASE-OS-Website sync workflow is retired and contains no credential, checkout, repository reference, or push operation.
- The minimum execution-evidence substrate records distinct Producer, Reviewer, and Gatekeeper executions/capabilities and exact base/head/diff/scope. Its deterministic verifier recomputes paths/diff from Git objects, binds Gatekeeper identity from the live GitHub Actions runtime context, requires the explicitly selected `openai/gpt-6-luna` model with truthful availability/attestation fields, and rejects consumed/expired authorization. It does not implement model routing, model debate, adaptive model selection, or general Role-Based Model Orchestration.

The source-governance record is not a runtime authenticated-human decision and does not modify the gate-decision registry.
